# Техническая часть проекта

## 1. Устройство

Приложение состоит из локального HTTP-сервера и страницы, которая выполняет расчёты в браузере.

Использованы Node.js, JavaScript, HTML и CSS. Внешние пакеты, база данных, нейросеть и платные API не подключены.

Это позволяет запускать проект без установки зависимостей и без интернета. Интернет нужен только для открытия правовых источников по ссылкам.

## 2. Запуск в Git Bash

Из папки проекта:

```bash
node server.js
```

Из любой папки:

```bash
/c/nodejs/node.exe 'C:/Users/MAX/Desktop/BusinessForm/server.js'
```

После запуска откройте http://127.0.0.1:8765. Для остановки нажмите Ctrl+C. После изменения исходников перезапустите сервер: содержимое файлов считывается при старте.

## 4. Путь данных

1. Пользователь выбирает цель.
2. app.mjs определяет видимые вопросы через goalFields.
3. Ненужные поля скрываются и отключаются.
4. При отправке HTML-форма проверяет обязательность и числовые ограничения.
5. FormData собирает доступные ответы.
6. rank() возвращает список кандидатов и основания оценки.
7. Интерфейс показывает лучшего кандидата и подробный разбор.
8. Для коммерческой цели buildExample() создаёт финансовый план, а calculate() вычисляет результат.

Каждое изменение анкеты скрывает старый результат. При переходе между специальными статусами динамические вопросы создаются заново, поэтому ответы от предыдущего статуса не переносятся.

## 5. Подбор

### compare()

Для обычного бизнеса вычисляет ограничения и соответствие шести критериям. Возвращает объект для каждой формы с ключом, баллом, объяснениями и ограничениями.

### signedRows()

Преобразует промежуточные значения в знаковые вклады по формуле вес × (2 × соответствие − 1).

### rankCore()

Выбирает ветку по цели. В аграрной и трудовой ветках добавляет КФХ и кооператив. В социальных целях формирует кандидатов НКО. Для особого статуса вызывает assessSpecial().

### rank()

Добавляет общие проверки, например число учредителей и конфликт распределения прибыли с социальной целью. Сортирует по наличию ограничений, затем по убыванию баллов.

Ограниченные формы остаются в разборе с причинами, но не становятся рекомендацией.

Если допустимых форм нет, приложение показывает конфликт, а не случайного победителя.

## 6. Данные особых форм

specialProfiles содержит описание, вопросы, следующие шаги, экономические особенности и источник для каждого направления.

assessSpecial() преобразует ответы в состояния confirmed, blocked и pending.

Итог blocked возникает при хотя бы одном отрицательном условии. При отсутствии отрицательных, но наличии неизвестных — pending. Все подтверждённые ответы дают preliminary.

Это самооценка по анкете. Система не проверяет документы и полномочия учредителей.

## 7. Экономический модуль

buildExample() формирует план по деятельности, масштабу и управлению.

calculate() принимает два объекта:

- plan — цена, продажи, затраты и параметры проекта;
- profile — расходы конкретной формы и налоговые допущения.

Функция возвращает выручку, расходы, налог и результат. Также реализованы дополнительные показатели безубыточности, рентабельности и окупаемости, не выведенные в текущий интерфейс.

Для нулевой выручки и неположительного результата показатели, требующие деления, возвращают null. Точка безубыточности также равна null при неположительном вкладе с продажи. При отображении это позволяет использовать прочерк вместо бессмысленного числа.

Сценарии спроса округляются до целых продаж. Финансовая арифметика использует стандартный JavaScript Number. Для бухгалтерской системы потребовалось бы более строгое управление округлением и денежными единицами.

## 8. Интерфейс

Используется обычная HTML-форма. Обязательные вопросы помечены required. Для чисел заданы min, max и step.

Поля имеют подписи. Дополнительные пояснения показаны рядом или в раскрываемых блоках. Список баллов скрыт по умолчанию, чтобы не перегружать пользователя.

Результат прокручивается в область просмотра. Таблицы могут прокручиваться по горизонтали. В стилях предусмотрено размещение полей в один столбец при узком экране.

В программных тестах UI используется модель DOM. Дополнительно основные ветки проходились в настоящем браузере.

## 9. Как работает сервер

server.js использует встроенные модули node:http, node:fs и node:path.

127.0.0.1 означает адрес этого ноутбука. 8765 — выбранный порт. Сервер предназначен для локальной учебной демонстрации.

Сервер заранее считывает фиксированный набор ресурсов из public/. Он не преобразует произвольный URL в путь на диске.

Для запроса:

1. Выставляются защитные заголовки.
2. Проверяется Host.
3. Проверяется метод.
4. Проверяется наличие пути в карте разрешённых ресурсов.
5. Возвращаются содержимое и подходящий Content-Type.

Коды ответа:

- 200 — ресурс отдан;
- 403 — неподходящий Host;
- 404 — путь отсутствует;
- 405 — метод не поддерживается.

HEAD отдаёт заголовки без тела. Если порт занят, выводится сообщение с предложением остановить предыдущий сервер.

## 10. Безопасность

- Сервер привязан к loopback-адресу.
- Отдаётся только фиксированный список файлов.
- Разрешены GET и HEAD.
- Нет обработчиков записи, загрузки файлов и выполнения команд.
- Нет БД и сохранения анкеты.
- Нет отправки ответов внешнему API.
- CSP разрешает скрипты и стили со своего адреса и запрещает встраивание страницы в чужой фрейм.
- X-Content-Type-Options задаёт nosniff.
- Cache-Control задаёт no-store.
- Пользовательские данные в объяснениях устанавливаются через textContent.

HTTP используется для локальной демонстрации. При публикации в интернете понадобятся отдельный пересмотр размещения, HTTPS, сетевой конфигурации и защиты.

## 11. Проверки

Из папки проекта:

```bash
node tests/check.cjs
```

Проверяются специальные условия с положительными, отрицательными и неизвестными ответами, пути подачи всех специальных анкет, возвращение к бизнесу, финансовый контрольный пример, основные цели, сочетания ответов НКО и карточки пояснений.

Ранее дополнительно проверены семь HTTP-сценариев на работающем сервере: допустимые ресурсы, попытка запроса служебных файлов и неподдерживаемый метод.

В браузере проходились бизнес, НКО, несовместимые ответы, кооператив, КФХ, общая недвижимость и особый статус. Это контрольные сценарии, а не перебор всех возможных ответов.

## 12. Почему нет нейросети

Выбор основан на правилах и коэффициентах. Для лабораторной это позволяет показать, откуда взялась рекомендация, повторить результат и вручную проверить расчёт.

Нейросеть можно было бы использовать для объяснений, но тогда потребовались бы дополнительные проверки достоверности и условия бесплатного локального запуска. В текущем проекте все результаты воспроизводятся без внешней модели.

## 13. Что можно развить

Для будущего развития: экспертная калибровка весов, более подробные отраслевые условия, версионирование правовых правил и полноценная налоговая модель.

Эти функции не заявляются как реализованные. На защите важно различать текущую функциональность, внутренние вычисления модуля и планы развития.

Кратко о технической реализации:

> Node.js отдаёт локальную страницу и модули. Браузер собирает ответы, выполняет правила выбора и финансовые расчёты. Алгоритмы отделены от отображения, поэтому их можно проверять автоматически и изменять независимо от оформления.
