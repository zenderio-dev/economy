# Техническая часть

Приложение написано на React и JavaScript. Vite запускает локальный сервер и собирает статические файлы. React Aria управляет взаимодействием с выпадающими списками и связывает поля с проверкой формы. Подбор формы и финансовый пример рассчитываются в браузере по правилам и заданным коэффициентам. Приложение не хранит ответы и не отправляет их на сервер.

## Исходники

| Путь | Ответственность |
| --- | --- |
| `index.html` и `src/main.jsx` | HTML-страница и запуск React |
| `src/App.jsx` и `src/questionnaire/` | Анкета, переключение вопросов и отправка ответов |
| `src/ui/` | Общие поля и кнопки |
| `src/domain/` | Каталог, ограничения, оценка кандидатов и финансовые формулы |
| `src/results/` | Рекомендация, сравнение, специальные условия и финансовая таблица |
| `src/styles.css` | Общие цвета, типографика и разметка страницы |
| `tests/` | Проверки предметных правил и поведения React-анкеты |

## От анкеты к результату

1. Цель определяет разделы анкеты. Поля, которые не относятся к выбранной ветке, отсутствуют в форме.
2. Браузер проверяет обязательные ответы и числовые ограничения, контролы показывают подсказки рядом с ошибками. При отправке `FormData` собирает ответы текущей ветки.
3. `rank()` возвращает кандидатов, их ограничения и объяснения оценки. Для особых форм `assessSpecial()` проверяет отдельные условия и сообщает, что подтверждено и что требует уточнения.
4. React выводит допустимый вариант с наивысшей оценкой или показывает конфликт условий. Изменение любого ответа скрывает предыдущий результат.
5. `compareFinances()` строит условный месячный план и сравнивает допустимые ИП, ООО и АО при одинаковой выручке.

Предметные модули отделены от React. Это позволяет проверять формулы и ограничения на фиксированных ответах и менять интерфейс независимо от логики подбора.

## Локальный запуск

Команда `npm run dev` поднимает Vite на `127.0.0.1:8765`. Инструкция по установке, запуску и проверкам приведена в [README](../README.md).

## Почему логика отделена от интерфейса

Предметные функции принимают ответы и возвращают результат, а React отображает его. Это позволяет проверить условие для ООО или расчёт выручки без нажатия кнопок в браузере.

Предметная модель отражает экономические понятия: участники, капитал, риск, критерии и расходы. Компоненты переводят их в понятные вопросы и таблицы.

## Три состояния обычного кандидата

В новой версии кандидат содержит исключения excluded и неподтверждённые условия pending.

Форма доступна для окончательной рекомендации внутри модели только если оба списка пусты. При обязательном ответе «пока не знаю» система сообщает, что требуется уточнить. Это не превращает неизвестный ответ в подтверждение.

Баллы хранятся отдельно от допустимости. Поэтому сортировка не делает исключённую форму подходящей.

## Разработка, локальный просмотр и публикация

Нужен Node.js 22.12 или новее. После установки зависимостей по package-lock.json:

```bash
npm ci
npm run dev
```

Vite запускается на 127.0.0.1:8765. strictPort не позволяет автоматически перейти на другой порт, если указанный занят.

Проверки и сборка:

```bash
npm test
npm run build
```

npm run preview показывает собранное приложение. Порт preview проверяйте по сообщению терминала: он отдельно не задан в vite.config.js.

На GitHub Pages публикуется результат сборки. Исходный Vite-сервер там не работает. Наличие workflow ещё не подтверждает успешную публикацию: результат нужно проверять в Actions и по адресу сайта.

## Границы технической проверки

Предметные тесты проверяют ограничения и финансовые формулы. Тесты анкеты проверяют отображение вопросов, обязательность ответов и переходы. Сборка проверяет совместимость модулей.

Ни один из этих шагов отдельно не подтверждает полноту правовой модели. Правила и документы проверяются содержательно, а доступность, внешний вид и поведение — также в браузере.
